# Crisp ASR 0.3.0 Implementation Plan

Target: ALL vault only  
Method: test-driven development, one failing behavior at a time

## 1. Settings and persisted models

- Extend settings tests for input mode, microphone, recording defaults and
  folder normalization.
- Add file-job validation, startup recovery and 100-entry retention tests.
- Run the focused tests and confirm they fail for missing 0.3.0 fields.
- Implement normalized 0.3.0 settings and queue job types.
- Re-run focused tests, then the existing settings suite.

## 2. Audio input

- Test microphone enumeration, default-device fallback and source-mode
  acquisition.
- Test missing shared-audio rejection and one-shot input-ended signaling.
- Confirm the focused tests fail.
- Implement `audio-input.ts`.
- Re-run focused tests.

## 3. Mixing, PCM and level

- Test pure RMS/level smoothing and packet buffering first.
- Test the browser audio graph with narrow fakes for one- and two-source modes,
  cleanup, level reset and mixed MediaStream exposure.
- Confirm each focused test fails before implementation.
- Implement `audio-mixer.ts` and adapt `LivePcmCapture` into the coordinator.
- Re-run audio tests and existing audio regressions.

## 4. Optional live recording

- Test MIME capability failure, chunk finalization, vault-folder creation,
  collision-safe paths and playable WebM byte persistence.
- Confirm focused failures.
- Implement `live-recorder.ts`.
- Re-run recorder tests.

## 5. Persistent serial queue

- Test serial execution, duplicate prevention, three-attempt limit, permanent
  failure behavior, restart recovery, manual retry/removal and pruning.
- Confirm focused failures.
- Implement dependency-injected `transcription-queue.ts`.
- Re-run queue tests.

## 6. Service error classification

- Add tests for retryable network/408/429/5xx failures and permanent
  authentication/provider errors.
- Confirm focused failures.
- Add a typed ASR error at the service boundary.
- Re-run Flash client/service and queue tests.

## 7. Plugin integration

- Test startup ordering: acquire input before opening the streaming connection.
- Test idempotent stop, input-ended stop, recording embed, queue persistence
  and startup resume.
- Confirm focused failures.
- Integrate the audio coordinator, recorder and queue into `main.ts`.
- Re-run interaction and live-resource tests.

## 8. View and settings UI

- Add DOM tests for three input modes, microphone visibility, refresh, save
  toggle, level meter and queue actions.
- Confirm focused failures.
- Update `asr-view.ts`, `settings-tab.ts` and `styles.css`.
- Re-run DOM and CSS tests.

## 9. Release and verification

- Update package, manifest and versions metadata to 0.3.0.
- Update README with permissions, macOS picker behavior, queue recovery and
  saved-audio location.
- Run `npm test`, `npm run build` and `npm run check`.
- Snapshot ALL `data.json` and all YS Crisp ASR hashes.
- Deploy only `main.js`, `manifest.json`, and `styles.css` to ALL.
- Reload Crisp ASR in Obsidian and inspect plugin/runtime errors.
- Verify deployed artifact hashes match source.
- Verify ALL `data.json` and all YS hashes are unchanged.
