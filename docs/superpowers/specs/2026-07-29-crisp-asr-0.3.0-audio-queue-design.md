# Crisp ASR 0.3.0 Audio and Queue Design

Status: Approved for implementation  
Date: 2026-07-29  
Target: ALL vault only

## Goal

Extend Crisp ASR without turning it into a broad recording-management suite.
Version 0.3.0 adds four focused capabilities:

1. Microphone selection and a live input-level meter.
2. Optional preservation of the audio actually sent to ASR.
3. A persistent, serial file-transcription queue with retry and restart
   recovery.
4. macOS computer-audio capture for meetings and media playback.

## Confirmed product decisions

- Live input offers three modes: microphone, computer audio, and computer
  audio plus microphone.
- Computer audio always uses the macOS system sharing picker. Crisp ASR never
  captures it silently.
- Saving live audio is disabled by default.
- Saved audio represents the actual mixed ASR input.
- Saved recordings use WebM/Opus in `Crisp ASR/Audio`.
- File transcription is serial.
- Retryable failures receive two automatic retries.
- Configuration, missing-file, decode, and size errors do not retry.
- Interrupted queued or running jobs resume when Obsidian restarts.
- Final failures remain available for manual retry or removal.

## Scope boundaries

Version 0.3.0 does not add mobile support, speaker diarization, multiple ASR
providers, LLM processing, hidden background system capture, or continuous
editing of the target Markdown file while speech is still in progress.

## Architecture

### `audio-input.ts`

Owns device discovery and MediaStream acquisition.

- Enumerates `audioinput` devices.
- Presents a stable "system default" choice plus available microphone labels.
- Falls back to the system default if a saved device disappears.
- Does not request microphone permission on plugin load. The refresh action or
  live-session start may request permission, then refresh device labels.
- Acquires microphone streams with echo cancellation, noise suppression, and
  automatic gain control.
- Acquires computer audio with `getDisplayMedia({ video: true, audio: true })`.
- Requires an audio track from the system picker.
- Retains the unconsumed video track only to keep the system sharing session
  alive; video frames are never read, recorded, or sent.
- Stops every acquired track on cleanup.
- Emits a single input-ended signal when the user stops sharing or a device is
  disconnected.

### `audio-mixer.ts`

Owns the live Web Audio graph.

- Accepts one or two acquired audio streams.
- Mixes sources to a mono bus.
- Uses a compressor/limiter to reduce clipping in combined mode.
- Resamples the bus to 16 kHz PCM16 packets for Doubao streaming.
- Calculates an RMS-based, smoothed level from 0 to 1.
- Throttles UI level callbacks to at most ten updates per second.
- Exposes the mixed bus as a MediaStream for optional recording.
- Does not create or own source permissions.

The existing `LivePcmCapture` becomes the coordinator around input acquisition
and mixing rather than directly requesting the default microphone.

### `live-recorder.ts`

Owns optional live-audio persistence.

- Starts a `MediaRecorder` on the mixed bus with
  `audio/webm;codecs=opus`.
- Collects bounded chunks during the session.
- On stop, creates a vault file named
  `Crisp ASR/Audio/live-YYYYMMDD-HHmmss.webm`, with collision-safe suffixes.
- Returns the vault path so the transcript can embed `![[path]]`.
- A recording failure produces a warning but does not discard a valid
  transcript.
- If WebM/Opus is unavailable while saving is enabled, session startup fails
  before capture begins so the user is not falsely promised an audio file.

### `transcription-queue.ts`

Owns file-job persistence and serial execution.

Each stored job contains:

- `id`
- `sourcePath`
- optional `targetPath`
- `status`
- `attempt`
- `createdAt`
- `updatedAt`
- optional `nextAttemptAt`
- optional `lastError`
- optional `outputPath`

Statuses are `queued`, `preparing`, `transcribing`, `retry-wait`, `completed`,
and `failed`.

The queue:

- Runs one job at a time.
- Rejects duplicate non-terminal jobs for the same source.
- Persists after every state transition.
- Converts `preparing`, `transcribing`, and `retry-wait` jobs back to `queued`
  during startup recovery.
- Resumes after Obsidian layout readiness when a configured API key is
  available.
- Retries retryable failures after short bounded delays, at most twice.
- Counts the first run plus two automatic retries as at most three total
  attempts.
- Retains the newest 100 jobs and always preserves non-terminal or failed
  jobs.
- Supports manual retry and removal.

The queue runner receives transcription and persistence dependencies instead
of importing Obsidian directly, so its state transitions can be tested with
real in-memory implementations.

## Start and stop flow

System capture must preserve the click's user activation. Live startup
therefore runs in this order:

1. Validate settings and freeze the active target note.
2. Acquire the selected input streams immediately, showing the system picker
   when required.
3. Connect the Doubao WebSocket.
4. Start the mixer and optional recorder.
5. Stream PCM packets, transcript updates, and level values.

If any later step fails, all earlier resources are released in reverse order.

Normal stopping runs in this order:

1. Stop new PCM production.
2. Finalize the optional MediaRecorder while the mixed audio bus is still
   alive.
3. Finish the Doubao stream and obtain the final transcript.
4. Write the transcript and optional audio embed.
5. Stop all input tracks and close the audio graph.

If an input track ends unexpectedly, Crisp ASR performs the same graceful stop
and writes the partial result rather than abandoning it. The stop coordinator
is idempotent, so a simultaneous button click, ended event, and unload cannot
finalize or write the same session more than once.

## User interface

The real-time card adds:

- Input-mode dropdown.
- Microphone dropdown, visible for microphone and combined modes.
- Device-refresh button.
- Save-recording toggle.
- Live level meter.

Input controls are disabled while connecting, listening, or finishing. Device
changes apply to the next session. The level meter is reset to zero whenever no
live session is active.

The jobs card shows persistent entries with status, attempt information, and:

- Retry for failed jobs.
- Remove for terminal jobs.
- Open result for completed jobs.

Settings add:

- Default input mode.
- Preferred microphone.
- Save live audio, default off.
- Live audio folder, default `Crisp ASR/Audio`.

## Settings migration

Existing 0.2.2 data remains valid. New normalized defaults are:

- `liveInputMode: "microphone"`
- `microphoneDeviceId: "default"`
- `saveLiveAudio: false`
- `liveAudioFolder: "Crisp ASR/Audio"`
- `fileJobs: []`

The API key remains in Obsidian SecretStorage. Device IDs and queue metadata
are not secrets.

## Error classification

Retryable:

- Network interruption.
- Timeout.
- HTTP 408, 429, or 5xx.
- Temporary WebSocket/service unavailability.

Permanent:

- Missing or invalid API key.
- HTTP 400, 401, or 403.
- Missing source file.
- Unsupported or undecodable audio.
- Processed audio over 100 MB.
- Invalid provider response.

Errors use a typed `retryable` property at the service boundary. Queue logic
does not infer retryability by matching translated UI messages.

## Verification

Automated tests cover:

- Settings migration and invalid-device fallback.
- Device filtering and source-mode acquisition rules.
- Mixed PCM and level calculations.
- Recorder MIME selection, chunk finalization, and filename collision.
- Queue serialization, duplicate prevention, retry limit, permanent failures,
  manual retry, removal, and restart recovery.
- Cleanup after acquisition, connection, recorder, and input-ended failures.
- Panel controls, level updates, and job actions.
- Existing Doubao protocol, file routing, transcript, and CSS regressions.

Runtime acceptance in ALL covers:

- Existing 0.2.2 settings and SecretStorage reference remain unchanged.
- Default microphone and a selected microphone can start and stop.
- Level meter reacts and returns to zero.
- Saving off creates no audio file.
- Saving on creates one playable WebM file and embeds it in the transcript.
- Computer-audio and combined modes show the macOS picker and reject a source
  without shared audio.
- A synthetic interrupted file job recovers after plugin reload.
- Obsidian reports no plugin errors or error-level console messages.
- Source and deployed runtime artifacts match.
- YS runtime and data hashes remain unchanged.
