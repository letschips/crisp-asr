# Crisp ASR 0.5.0 Creation Workbench Design

## Product boundary

0.5.0 turns Crisp ASR from a transcription panel into a voice-first creation workbench. Personal dictation and content creation remain primary. Meetings and interviews gain speaker separation and renaming, but do not replace the main creation flow.

The release contains five connected capabilities: dictation profiles, terminology/context enhancement, live creation markers, a staged AI creation workflow, and speaker-aware transcription. Existing 0.4.16 microphone, queue, recovery, privacy, and original-text protection behavior remains intact.

## Dictation profiles

The start panel exposes seven profiles: free dictation, idea capture, long-form article, video script, Xiaohongshu post, meeting/interview, and custom. A profile contributes a short ASR scene context and a staged creation instruction. The selected profile persists but can be changed before each session.

The custom profile has a user-visible name, context and creation instruction. Profiles never silently start AI processing after transcription.

## Terminology and current-note context

Users can maintain newline-separated local hotwords and an optional Volcengine boosting table ID. The plugin builds the documented `request.corpus` object for both live and file recognition. Direct hotwords are serialized into `corpus.context`; the table ID is serialized into `corpus.boosting_table_id`.

When current-note context is enabled, the active note title, aliases, tags and a bounded beginning of the note are added as recent dialog context. The final serialized context is bounded before sending. API keys remain in SecretStorage; context and terminology are ordinary plugin settings and are described in the privacy notice.

## Live creation markers

During live listening the panel exposes three actions: important, new paragraph and needs confirmation. Each marker records elapsed time and the current finalized-utterance index. Markers are shown in the live stream, persisted in the recovery draft, and rendered into the final Markdown at a deterministic boundary.

Markers do not use spoken command detection. They never alter ASR audio or recognition sequences.

## Staged creation workflow

The smart-processing area adds “Generate creation draft”. It remains a user-triggered action and uses the already configured AI provider.

The workflow runs four sequential stages:

1. clean transcript while preserving facts;
2. extract and order the core ideas;
3. produce a profile-specific draft;
4. generate title or hook candidates.

The existing protected preview modal shows all stage results under separate Markdown headings and reports the current stage. Applying uses the existing same-note/new-note policy and never overwrites the raw transcript.

## Speaker-aware transcription

An opt-in “identify speakers” setting adds the documented `enable_speaker_info`, `ssd_version: "200"`, and live `enable_nonstream` request fields. The parser accepts speaker IDs from documented or compatibility response locations without inventing identities.

Speaker-aware Markdown stores stable HTML markers plus a visible default label such as “Speaker 1”. The panel and command palette expose a rename action. Renaming changes only visible speaker labels while stable markers remain, allowing repeated edits.

## Privacy and safety

- No automatic AI call after transcription.
- Local hotwords and active-note context are sent only to Volcengine when recognition starts.
- Raw transcript and stable speaker markers are preserved during AI processing.
- No new runtime dependency, proxy server, system-audio capture or cloud synchronization.
- Old settings normalize to free dictation, no hotwords, current-note context off and speaker identification off.

## Acceptance

- Request builders cover profile context, direct hotwords, boosting table ID and speaker fields for live and file APIs.
- Markers survive recovery and render at correct utterance boundaries.
- Four-stage creation runs in order, reports stage progress and preserves the original transcript.
- Speaker IDs parse, render and rename deterministically.
- Settings and panel controls are tested, aligned and backward-compatible.
- Full checks pass, ALL/YS runtime artifacts match, both vault data files stay distinct, and a sanitized Desktop ZIP is produced.
- GitHub publication of 0.5.0 waits for user testing.
